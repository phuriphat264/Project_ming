1. สรุปภาพรวมและที่มาของปัญหา (Executive Summary)

ปัญหาเดิมของสถานประกอบการ: บริษัท มาตัง คอสเมติก จำกัด มีคำสั่งซื้อผ่าน TikTok Shop เฉลี่ย 30,000–50,000 ออเดอร์/เดือน ฝ่ายบัญชีต้องใช้สูตร VLOOKUP และ SUMIFS เชื่อมโยงไฟล์รายงาน Excel หลายชุดด้วยตนเอง ซึ่งทำให้:

  • เสียเวลาปิดงบนาน 3–5 วันทำการ ต่อเดือน
  • ปัญหาคิดต้นทุนซ้ำซ้อน (Double-Counting COGS): ออเดอร์ที่มีแถวคืนเงินค่าจัดส่งย้อนหลัง (6–13 บาท) จะมี 2 แถวใน Settlement ทำให้สูตร Excel เดิมคิดต้นทุนสินค้าเบิ้ล 2 รอบ (ในเดือน ก.ย. 69 ต้นทุนบวมเกินจริงไปถึง 28,240 บาท)
  • ปัญหาออเดอร์ข้ามงวด (Cross-Month Gap): เงินโอนเข้าเดือนนี้ แต่ออเดอร์สร้างเดือนก่อน ทำให้หารายการสินค้าไม่เจอ ต้องไปก๊อปปี้ไฟล์เก่ามารวมด้วยมือ
  • ขาดการวิเคราะห์เชิงลึก: ตรวจไม่พบออเดอร์ที่ขายขาดทุน และจำลองผลกระทบการปรับราคา/ค่าแอดไม่ได้

ผลลัพธ์ของระบบใหม่: ประมวลผล 32,714 รายการเสร็จใน 11.4 วินาที (ลดเวลาลงกว่า 99%) พร้อมระบบ COGS Deduplication และ Order Repository ขจัดข้อผิดพลาด 100%

2. สถาปัตยกรรมและโครงสร้างสูตรการคำนวณ (Calculation Engine)

2.1 ระดับรายการสินค้า (Order Line Item)

net_qty = max(0, Quantity - Sku_Quantity_of_Return) [ถ้ายกเลิกคำสั่งซื้อ = 0]
ราคาต่อหน่วย (Col I) = VLOOKUP(Seller SKU, SKU Master, unit_cost)
มูลค่าต้นทุนสุทธิ (Col J) = ราคาต่อหน่วย (Col I) × net_qty

2.2 ระดับคำสั่งซื้อ (Order Settlement Level)

ยอดการชำระเงินทั้งหมด (Col F) = ยอดขายสุทธิ - ค่าธรรมเนียมแพลตฟอร์มทั้งหมด + จำนวนการปรับยอด
ต้นทุนรวมสินค้า (Col G) = SUM(Order!Col J) [คิดเฉพาะแถวธุรกรรมหลัก แถวคืนค่าส่งเซ็ตเป็น 0]
กำไรรายออเดอร์ (Col H) = ยอดชำระเงินทั้งหมด (Col F) - ต้นทุนรวมสินค้า (Col G)

2.3 งบกำไรขาดทุนของบริษัท (Company P&L)

Rough Profit = SUM(Col H) - ค่าโฆษณาภายนอก
Sales Commission = max(0, Rough Profit × % ค่าคอมฯ)
Fixed Costs = ค่าแรง + ค่าน้ำ + ค่าไฟ + ค่าเช่า + ค่ากล่องพัสดุ
Net Profit = Rough Profit - Sales Commission - Fixed Costs
จุดคุ้มทุน (BEP) = Fixed Costs ÷ Contribution Margin Ratio

3. สรุปผลการทดสอบระบบ (Testing & Validation Results)

มิติการทดสอบ ผลการทดสอบด้วยมือเดิม (Excel) ผลลัพธ์จากระบบอัตโนมัติ (Python) ผลสัมฤทธิ์ที่ได้
ความแม่นยำของตัวเลขทางการเงิน ต้นทุนบวม 28,240 บาท จากการคิดต้นทุนซ้ำในแถวคืนค่าส่ง คำนวณถูกต้องตามหลักการบัญชีจริง 100% บริษัทรับรู้กำไรสุทธิแท้จริงเพิ่มขึ้น 28,240 บาท
ระยะเวลาในการประมวลผล (32,714 ออเดอร์) ใช้เวลา 3 ถึง 5 วันทำการ (เครื่องคอมฯ ค้างบ่อย) ประมวลผลเสร็จสิ้นใน 11.4 วินาที ลดระยะเวลาการทำงานลง 99.9%
การจัดการคำสั่งซื้อข้ามงวด ต้องเปิดไฟล์เดือนก่อนหน้ามาตัดยอดด้วยมือ ดึงจากคลัง Order Repository อัตโนมัติ นำเข้าเฉพาะไฟล์เดือนใหม่ไฟล์เดียวได้ทันที
การประเมินความพึงพอใจ - คะแนนเฉลี่ย 4.90 เต็ม 5.00 อยู่ในเกณฑ์ 'มากที่สุด' จากผู้ใช้งานจริง

4. แนวทางการตอบคำถามกรรมการสอบโครงงาน (Defense Q&A)

Q1: จุดเด่นและนวัตกรรมหลักของโปรเจกต์นี้คืออะไร เมื่อเทียบกับการใช้โปรแกรม Excel ทั่วไป?
คำตอบ: จุดเด่นหลักคือการเปลี่ยนจากการทำงานแบบ Manual ที่ต้องพึ่งพาแรงงานคนและสูตรสเปรดชีตที่เสี่ยงต่อความผิดพลาด มาเป็น End-to-End Data Pipeline ที่ทำงานอัตโนมัติ โดยมี 3 นวัตกรรมสำคัญ: 1) อัลกอริทึม COGS Deduplication ที่ตรวจจับออเดอร์หลายแถวใน TikTok เพื่อป้องกันการคิดต้นทุนสินค้าซ้ำ 2) สถาปัตยกรรม Order Repository ที่ใช้ไฟล์ Parquet บันทึกคำสั่งซื้อสะสมข้ามงวด 3) Financial Simulation & Anomaly Detection ที่สามารถจำลองราคาแบบ What-If และตรวจจับออเดอร์ขายขาดทุนได้ทันที
Q2: ทำไมจึงเลือกใช้ Parquet ร่วมกับ SQLite แทนที่จะใช้ MySQL หรือฐานข้อมูลขนาดใหญ่?
คำตอบ: เนื่องจากระบบถูกออกแบบให้ติดตั้งใช้งานภายในเครื่องของฝ่ายบัญชีและโรงงาน (Lightweight & Standalone) การใช้ SQLite ช่วยให้ไม่ต้องติดตั้ง Database Server ภายนอก ส่วนการใช้ Parquet เก็บประวัติคำสั่งซื้อสะสม เพราะ Parquet เป็น Columnar Storage ที่มีอัตราการบีบอัดสูงมาก ประหยัดเนื้อที่ดิสก์ และเวลาอ่านคอลัมน์เพื่อคำนวณจะเร็วกว่าไฟล์ Excel ทั่วไปถึง 10–20 เท่า ทำให้ประมวลผล 3 หมื่นแถวได้ใน 11 วินาที
Q3: หาก TikTok มีการเปลี่ยนรูปแบบหัวตารางหรือมีคอลัมน์ใหม่ ระบบจะทำงานได้หรือไม่?
คำตอบ: ระบบถูกออกแบบให้รองรับผ่านโมดูล core/loader.py ซึ่งมีระบบ Column Mapping แบบยืดหยุ่น รองรับทั้งชื่อหัวตารางภาษาไทยและภาษาอังกฤษ (Global Format) และตรวจสอบคอลัมน์สำคัญ (Required Keys) หากมีคอลัมน์ใหม่เพิ่มเข้ามา ระบบจะไม่พัง และหากมีรหัสสินค้าใหม่ที่ไม่มีราคาทุน ระบบจะมีระบบ Missing SKU Warning แจ้งเตือนฝ่ายบัญชีให้ไปกรอกราคาทุนทันที
